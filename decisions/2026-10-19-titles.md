# Conversation titles and summaries from a small model

Status: accepted (2026-10-19)

## Context

Kevin: "I need the model to correct the thread title/summary on each
reply. Right now they all just say 'New Study'." The phone app created
every conversation as "New study" (`Bezalel.Views.Conversations`) and
nothing renamed it; the website named one after the first line of its
first question (`BezalelCa.Library.name_after/2`) and never again, so a
conversation that moved on kept its first question as its name. Neither
had a summary.

## Decision

- `Bezalel.Agent.Title` (here, so both apps name the same way) writes a
  title (6 words asked, 8 kept) and a one-sentence summary from the
  conversation so far: each question, each reply's SUMMARY (not its
  thinking or tool calls) and each critique, cut per message, the first
  question and the newest messages when it's long. The current title and
  summary go along once there is a summary, so the model keeps them while
  they fit and changes them when the topic drifts; a title without a
  summary is a placeholder or the first question, not something to keep.
- The model is the lead's provider's small one, found in rho's catalog by
  name: Claude Haiku, a GPT mini (then nano), Gemini Flash-Lite (then
  Flash), ChatGPT's Luna (the Codex backend's "fast and efficient" model);
  the lead itself when the catalog has none. Same provider, so the same
  sign-in or key pays for it and no second credential is needed.
- It goes through `Rho.Consult.run/3` with no loop: the credential is
  rho's, rho's usage record counts the call and its cost like any other,
  and nothing reaches the session, the chat or the loop's subscribers
  (a consult on the loop would show as a CONSULT block).
- The answer is two lines, `Title:` and `Summary:`, not JSON: req_llm
  1.28 turns a reply that is all JSON into an object part with no text
  (Claude Haiku 5.5 did, seen 2026-10-19), which Consult reports as "answered
  with no text". The parser also takes a JSON object, and labelled lines
  in Markdown or a list; nothing else, and both a title and a summary.
  Haiku leaves the labels off now and then (one answer in about twenty in
  the smoke runs); such an answer is unreadable and the name stays until
  the next reply, because two short unlabelled lines can't be told from
  a refusal.
- `from_question/1` is the name before the first title (the question's
  first line, cut at a word), shared by both apps, so a naming that fails
  leaves something better than "New study".
- The apps run it after a reply is stored, off the reply's path (a task),
  and keep the old name on any error. Neither app lets the user rename a
  conversation yet; when one does, it must not call this for a renamed
  one.

## Consequences

- One small-model call per finished reply (about $0.0005 with Haiku on an
  API key; on a subscription, a sliver of its window).
- A title arrives a second or few after the reply; the lists update when
  it does.
- The provider's small model must accept the sign-in: Haiku for Claude,
  Luna for ChatGPT; if a plan stops serving the one picked, naming fails
  quietly and the name stays as it was (the apps log why).
